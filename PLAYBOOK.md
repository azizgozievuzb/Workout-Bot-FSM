> переписки. До этого шапка не меняется. Собран сессией S61 (2026-08-07, Cowork Fable 5).

## 1. Цикл разработки (ядро, переносимое)

**Роли:** Cowork (Fable) — архитектор: дизайн-интервью, постановки, ревизия. CC (Claude Code CLI,
дефолтный Opus) — исполнитель: код, миграции, смоуки с БД. Юзер — решает всё продуктовое и
проверяет глазами.

**Шаг A — дизайн-интервью (Cowork + юзер).** Формат отработан в DESIGN_8D1 (финальная сверка —
ноль противоречий на ~15 вопросах): по одному вопросу за раз · каждый термин — с переводом и
привязкой к экрану · в каждом вопросе явная рекомендация с обоснованием, решение за юзером ·
эхо-фиксация (после ответа показать точную записанную формулировку) · шаблон записи
«решение → почему → что тянет» · «не знаю» легален: статус «отложено», фиксируется дефолт +
условие возврата · в конце — сверка всех решений на противоречия. Решения пишутся в файл
СРАЗУ, по ходу интервью (сессия может умереть в любой момент — причина в §6-фикс).

**Шаг B — постановка (Cowork → промпт для CC).** Перед промптом — Meta-блок (effort / ultrathink /
transcript; формат и таблица подбора — CLAUDE.md, AGENT PROMPT-DELIVERY RULE, не дублируем).
**Политика моделей — решена, не изобретать заново:** модель НЕ выбирается под задачу
(CC = текущий дефолтный Opus, Cowork = Fable); выбирается только effort. Причина (решение юзера
2026-07-16): выбор модели на каждый промпт — лишнее решение без пользы, дефолт вендора
обновляется сам; переносимый принцип — «фиксируй модель, крути усилие».

**Шаг C — исполнение (CC) + протокол «остановись и спроси».** Исполнитель обязан остановиться
и спросить юзера, когда: (а) задание задевает ИНВАРИАНТ продукта (список — CLAUDE.md);
(б) для продолжения нужна догадка о продуктовом смысле — догадка запрещена, вопрос обязателен;
(в) задача требует запрещённого коннектора (CLAUDE.md §Коннекторы). Технические решения «на
усмотрение исполнителя» разрешены, но фиксируются явным блоком «Допущения» в SESSION_STATUS
(паттерн S53/S56/S58) — молчаливое допущение неотличимо от бага. Причина протокола: все крупные
инциденты проекта — из зоны, где исполнитель ЗНАЛ, что сомневается (пример: смоук S52 п.5 —
красная кнопка оказалась abort-ом, вопрос «а как надо?» всплыл только на живом прогоне).

**Шаг D — проверка по диффу и файлам, НЕ по отчёту.** Отчёт исполнителя — сжатая интерпретация;
проверяется первоисточник: дифф, файлы, БД. Оплаченная причина: «tsc → 0 ошибок» три сессии
подряд (S52–S54) было ложным зелёным — гейт компилировал 0 файлов; вскрылось не из отчётов,
а проверкой самого гейта (S56). Следствие: новый проверочный гейт доказывается подложенной
ошибкой (санити-проба), см. урок №6.

**Шаг E — живой смоук = определение «готово».** «Реализовано» (код написан, verify зелёный) ≠
«готово». Готово — только после живого смоука. Формат, который себя оправдал (S57/S59, колаут
ORIENTATION): ведущий даёт по ОДНОМУ пункту (что нажать / что должно быть видно) · ожидание
формулируется ИЗ БД до действия · результат подтверждается SELECT-ом, не на слово · прогон на
реальных устройствах обеих ролей (десктоп наставника + iPhone игрока) · у каждой ветки с
опциональным параметром проходятся ОБА пути (урок №1) · цены снижаются SQL-ом до 1⭐/1💧,
BEFORE-снимок фиксируется, после прогона откат сверяется 1:1 · мелочь чинится хотфиксом тут же
(отдельными коммитами), крупное — в находки/BACKLOG. Причина формата: класс багов, невидимых
в коде и симуляции, — урок №9.

**Шаг F — фиксация.** Решения, находки, допущения и уроки пишутся в файлы В МОМЕНТ появления
(SESSION_STATUS — журнал; DESIGN_* — решения дизайна; BACKLOG — идеи «на потом», 3–5 строк
«контекст + что делать + когда»; PLAYBOOK — уроки процесса). Причина: сессии смертны (лимиты
токенов, обрывы) — то, чего нет в файле, не существует; сама сессия S61 собрала процесс заново
исключительно из файлов, память переписок не понадобилась. Это и есть тест.

## 2. Принцип инвариантов

У проекта обязан быть короткий СПИСОК ИНВАРИАНТОВ — «нельзя ломать ни при каких условиях» — и
жить он обязан там, где исполнитель не может его не увидеть (у нас: CLAUDE.md, секция
«Инварианты продукта», с директивой «задел → стоп и вопрос»). Здесь список не дублируется.
Причина: до S61 инварианты были размазаны по журналам (§8.7 — в решениях S50, Э.9 — в
эконом-сессии) и держались на памяти; проверка «наставник не видит баланс» попадала в смоуки
только потому, что о ней помнили. При переносе в новый проект список составляется интервью
(«что нельзя ломать»), не копируется.

## 3. Коммуникация с юзером

Юзер — не разработчик. Директива «новый термин → перевод при первом употреблении» — в CLAUDE.md
(«Язык с юзером», введена S61 по инцидентам «колаут»/«казино-механика»). Переносимые принципы
сверх неё: по одному-два вопроса за раз · «не знаю» — легальный ответ (фиксируется дефолт +
условие возврата) · рекомендация всегда с причиной, решение за юзером · если ответ юзера
противоречит коду/фактам — сказать прямо и разобраться, что устарело: код или представление.

## 4. УРОКИ (только реально ломавшееся: симптом → фикс)

Пометки: [У] — универсальный, брать в любой проект; [П] — специфичен этому стеку/сетапу.

1. **[У] Ветка с опциональным параметром → смоук проходит ОБА пути.** Симптом: галочка
   «Выполнено» без видеоотчёта падала 400 два патча подряд (пустая FormData валила парсер до
   обработчика) — смоук S57 гонял только «богатый» путь с отчётом; бедный путь стал основным в
   8d.1 и сразу выстрелил (S59 🔴). Фикс: тело не отправляется без видео + правило смоука.
2. **[П] Порталы не наследуют тема-классы.** Симптом: кнопка «⬇ Скачать» с нативным видом,
   тост голым текстом — `createPortal(body)` вне дерева, где висят `.dark/.light-theme` (S59,
   дважды). Фикс: внутри порталов красить ТОЛЬКО `--tg-theme-*`-переменными (они на `:root`);
   нужен аудит всех порталов (BACKLOG S59 №4).
3. **[У] Состояние есть в логике — покажи его глазу.** Симптомы одной природы (S59): серая
   кнопка отвечала на тап без признаков жизни; disabled без стиля; подаренный кредит реролла
   списывался первым, но в UI не существовал — игрок смотрел на цену в каплях. Фикс: у каждого
   состояния — видимая проекция (стиль disabled, busy-лейблы, видимый кредит).
4. **[У] Превью обязано показывать реальный кадр.** Симптом: рекордер показывал крупный план,
   а в файл писался полный кадр — «в видео попало то, чего я не знал» (S59; та же обрезка — в
   селфи-капчере). Фикс: коробка превью в пропорции потока, кадр целиком (`contain`).
5. **[У] В AI-промпте неперечисленное = свободный параметр.** Симптом: промпты перечисляли что
   сохранять (геометрия, родинки, возраст), мимики в списке не было → модель переписала лицо
   (S59 №13). Фикс: явный пункт про мимику/взгляд + запреты; правило — список «сохранять»
   должен быть полным, модель не додумает.
6. **[У] Проверочный гейт доказывается подложенной ошибкой.** Симптом: `tsc --noEmit` на
   solution-style конфиге компилирует 0 файлов — три сессии ложного «0 ошибок» (S52–S54,
   вскрыто S56). Фикс: `npm run typecheck` = `tsc -b --force` + санити-проба (подложенная
   ошибка должна ловиться). Любой новый гейт — сначала доказать, что он умеет краснеть.
7. **[У] Смена модели доступа → grep ВСЕХ фильтров по старым полям.** Симптом: closure-джоб и
   напоминания фильтровали по `partnerships.expires_at` (промо-эпоха, у боевых пар NULL) —
   джобы НИКОГДА не видели боевых игроков (S54 🔴); тот же класс — гейт дарения заморозок
   (S56). Фикс: перевод на живую модель доступа + правило grep-а при каждой смене модели.
8. **[У] Смоук: ожидание из БД, подтверждение SELECT-ом, откат 1:1.** Не урок-инцидент, а
   выжимка формата S57/S59 (шаг E) — вынесено отдельно, потому что это главный переносимый
   артефакт процесса.
9. **[У] Часть багов ловится ТОЛЬКО живьём на реальных устройствах.** Три несимулируемых
   примера: Stars-счёт `send_invoice` не рендерится в чате, хотя API вернул message_id (S51);
   axios молча превращал FormData в JSON из-за Content-Type на инстансе (S57 🔴); iOS-webview:
   привязка камеры в `setTimeout(0)` → чёрное селфи 11 КБ уезжало в AI (S57 🔴). Фикс-правило:
   живой смоук на устройствах обеих ролей обязателен, симуляция не заменяет.
10. **[У] Мерить живой артефакт, а не предполагать.** Симптом: MediaRecorder писал ~1.2 МБ/с
    без лимита битрейта — 30-сек ролик упёрся бы в собственный потолок 30 МБ (замер файла из
    бакета, S57). Фикс: пресет C (явные битрейты) + перезамер после внедрения (S59: 0.87 МБ).
11. **[П] После `claude update` — полный перезапуск CC.** Симптом: список моделей вшит в
    запущенный бинарник — старая сессия показывала только Opus 4.8 (поймано 2026-07-29).
12. **[П] Cowork ≠ CC по коннекторам.** `my-supabase` есть только в CC; Supabase-MCP в Cowork —
    чужой (общий аккаунт) и запрещён. Любой SQL из Cowork — промптом для CC (CLAUDE.md, 2026-07-18).
13a. **[У] Снапшот UI-состояния врёт после успешной записи.** Симптом: форма снижения цены
    лота держала потолок, взятый при открытии; после успешного 200→100 она показывала старый
    диапазон, старую подпись «сейчас 200 💧» и пускала кнопку при 102 — сервер такой запрос
    отбивал (S63). Фикс: границы формы считать из живых данных страницы, а не замораживать при
    открытии; исчез объект — форма закрывается сама. Родня урока №3 с другой стороны: там
    состояние не показано глазу, здесь показано УСТАРЕВШИМ.
13b. **[У] Гейт бэка обязан быть и гейтом кнопки.** Симптом: смена графика на 30-дневном
    кулдауне отбивалась сервером (409, капли целы), но кнопка об этом не знала — игрок открывал
    окно подтверждения, где обещаны «Спишется 100 💧» и «вступят со следующего понедельника»,
    жал «Сменить» и получал отказ (S63). Фикс: каждое серверное «нельзя» имеет парную проекцию
    в UI (серая-но-живая кнопка + причина ДО окна траты). Проверка на смоуке: у каждого гейта
    пройти путь, где он срабатывает.
13c. **[У] Оплаченное, но отложенное — держать на экране постоянно, не тостом.** Симптом:
    игрок платил 100 💧 за смену дней, видел транзиентный тост и уходил; на экране следа не
    оставалось — «списали и ничего не произошло», а вступление в силу через неделю (S63; тот же
    класс — находка №11 S59). Фикс: пока покупка не вступила в силу, её результат виден
    постоянной строкой, а разница «сейчас / потом» — в самом виджете.
13d. **[П] Скрипт-обёртка смоука может стирать то, что проверяешь.** Симптом: `smoke_jobs_ab.py`
    перед каждым `job-a` обнуляет `last_renewal_reminder_at` и переставляет дату подписки —
    дедуп «не чаще 1/день» им проверить нельзя в принципе (S63). Фикс: гейты, которые скрипт
    сбрасывает, гонять прямым вызовом джоба; перед использованием чужого смоук-скрипта прочитать,
    что он пишет в БД.
14. **[У] Кладбища решений вести явно.** Секции «Отброшено при ревизии S50» / «Устарело» в
    BACKLOG не дают отвергнутому вернуться по незнанию (формула 10×days², множитель ×3,
    промо-как-оплата…). Отклонённое фиксируется С ПРИЧИНОЙ отклонения.

## 5. ЧЕГО НЕ ДЕЛАТЬ

1. **Не переносить чужие правила без проверки применимости.** Чужой опыт (opensource, индустрия,
   «так делают все») — источник ВОПРОСОВ к нашему контексту, не образец. Примеры-причины: индустрия
   пикает модель под задачу — у нас осознанно нет (шаг B); индустрия-пруфы эконом-сессии (Paired,
   Gottman) использовались как аргументы к обсуждению, а не как готовые решения.
2. **Не заполнять разделы заглушками «уточнится позже» — спросить юзера.** «Не знаю» юзера —
   легальный ответ и фиксируется как «дефолт + условие возврата» (это НЕ заглушка). Причина:
   заглушка без владельца = гниение; шаг 1 сессии S61 нашёл 9 расхождений именно в местах,
   которые «допишем потом» так и не дописали.
3. **Не писать по шаблону, не выросшему из фактов проекта.** Причина: STRUCTURE.md отклонён юзером
   ровно за это — пофайловая карта протухает с первого дня, а правды не добавляет; каждый раздел
   этого файла обязан ссылаться на инцидент или причину (приёмочный чек ниже).
4. **Не заводить второй источник правды на тот же тип информации.** Причина: PLAN.md и ROADMAP.md
   дублировали журнал/БД, протухли на 4 месяца и врали в постановки (таблица расхождений S61:
   боусты, промо-оплата, star_balance, NOTIFICATION_SETTINGS…) — итог: PLAN удалён, ROADMAP в
   `_archive/`, схема БД читается из живой БД и кода.
5. **Новый проект ≠ копипаста плейбука.** При старте нового проекта — интервью «что берём, что
   нет»: Cowork предлагает кандидатов с обоснованием ([У]-пометки — первые кандидаты), решение за
   юзером (правило юзера, 2026-08-07).

## 6. Правило жизни плейбука

- **Урок добавляется в момент закрытия смоука/сессии** — вместе с обновлением SESSION_STATUS
  (директива в CLAUDE.md, Workflow п.7). Формат урока: симптом → фикс, только реально ломавшееся.
- **Ревизия всего файла — при закрытии каждой фазы** (8d.x, 8e, …): устаревшие правила не
  удаляются молча, а переносятся в кладбище с причиной (урок №13 применён к самому плейбуку).
- **Триггеры внепланового обновления:** команда юзера или обновление SESSION_STATUS.
- **Фильтр на вход:** правило без причины/инцидента не вносится.
