## Кусок 1 — XP начисляется, уровни считаются ✅ (код готов, миграция не применена)

**Было:** `player_stats.global_score` существует, наставник его видит, `/stats/me`
отдаёт — и **ни одна строчка кода в него не пишет** (сверено по коду и SQL 01.09).

**Стало.** В `finish_session` XP = `round(workout_sessions.total_score × множитель)`,
под **тем же** антифарм-гейтом `already_earned_today`, что и капли: повторная сессия
типа за день даёт 0 XP ровно как 0 капель (инвариант №3). Свободная тренировка не
доходит до этого места вообще.

**Семь чисел экономики — в админке** (`app_settings`, миграция 039), не в хардкоде:

| Настройка | Дефолт | Что значит |
|---|---|---|
| `xp_mult_main` | 0.1 | XP = сумма баллов Gemini × это |
| `xp_mult_light` | 0.1 | то же для light |
| `level_base` | 500 | стоимость 1-го уровня |
| `level_early_step` | 1.25 | шаг удорожания до перелома |
| `level_late_step` | 2.0 | шаг после перелома |
| `level_boundary` | 3 | уровень перелома |
| `level_freeze_rewards` | `{"1":1,"2":2,"3":3}` | разовые заморозки за уровень |

Лестница из дефолтов (проверено прогоном формулы, совпадает с санити юзера 1:1):

```
уровень   1     2     3     4      5      6       7
стоит    500   625   781  1562   3125   6250   12500
всего    500  1125  1906  3468   6593  12843   25343
```
L3 ≈ 1906 XP ≈ месяц при 3 main/нед (main ≈ 140 XP), L6 ≈ 12.8k ≈ 7 месяцев. ✅

**Уровень не хранится** — считается формулой из общего `global_score`
(`backend/services/leveling.py`). Экран показывает «X из cost(N+1)»: шкала
визуально обнуляется на каждом уровне, счётчик в БД остаётся один, ничего не сгорает.

**`/stats/me` и досье наставника** отдают `xp / level / xp_in_level / level_cost`.
Баланс капель игрока наставнику не отдаётся нигде — инвариант №1 не задет
(§8.7 разрешает ровно уровень и XP-прогресс, его и отдаём).

**Админка — новая вкладка «XP»** (`AdminCube`): семь полей + **живой предпросмотр
первых 10 уровней** (стоимость, кумулятив, награда). Предпросмотр считает **бэк** и
присылает вместе с ответом — то есть админ видит ровно ту лестницу, по которой живут
игроки. Причина: Python `round()` округляет «к чётному» (1562.5 → 1562), а JS
`Math.round` — вверх (1563); два источника разошлись бы на единицу.

## Кусок 2 — награды за уровень ✅

Взятие уровня 1/2/3 → разовая выдача **+1 / +2 / +3 заморозки** в `paid_freezes`.

* **Почему `paid_freezes`, а не `free_freezes_left`:** месячный запас перезаписывается
  джобой 1-го числа (`grant_monthly_freezes`: Ж=3, М=1) — подарок за уровень там бы
  просто исчез. Решение юзера 02.09: это разовая выдача, не прибавка к запасу.
* **Кап 3 действует только на ДОКУПКУ** (`buy_paid_freeze`) и дарение наставником —
  уровневая выдача его может временно превысить (дефолт-рекомендация Cowork; проблемы
  не увидел: `paid_freezes` — smallint, покупка после превышения просто недоступна,
  пока запас не опустится ниже 3).
* **Идемпотентность — `player_stats.last_rewarded_level`.** Награждается интервал
  `(last_rewarded_level, текущий уровень]`; повторный финиш, пересчёт XP или ручная
  подкладка второй раз за тот же уровень не дадут.
* **Уведомление:** «🎉 Уровень N!» + «+K заморозки ❄️» (русские окончания считаются).
* Уровни 4+ наград не дают — числа в админке пустые, решение отложено (BACKLOG).

День вне плана (light-режим не куплен, сегодня не main-день) запускает **свободную**

получить начисления. `POST /workout/clip` для свободной сессии отвечает 409
(`FREE_SESSION_NO_CLIPS`) — гейт стоит на сервере, каждый клип это прямые деньги.

**Экран — на всю ширину** (`ws-stage--nocam`): вместо сетки 60/40 один ряд, HUD

**Никаких новых строк и плашек** (решение юзера 02.09, урок №21): правду говорит

## Допущения CC (S67)

1. **Свободная сессия — флаг `workout_sessions.is_free`, а не новый `session_type`.**
   `session_type` под CHECK ('main','light') и им параметризован движок (4 упражнения,
   light-тайминги) — расширять его значило бы трогать конфиг тренировки. Флаг
   ортогонален: тип отвечает за формат, флаг — за «оценивается ли».
2. **Свободная сессия НЕ пишет `last_workout_date`.** Это поле читают джоба
   напоминаний («уже тренировался сегодня») и джоба сломанного стрика — свободный день
   молча спасал бы стрик, а он не должен на него влиять. Никакие поля `player_stats`
   свободной сессией не трогаются вообще.
3. **Уровни начинаются с 0.** Новый игрок — «Уровень 0», первый уровень берётся на
   `level_base` (500 XP ≈ 3–4 main ≈ неделя, как в вехах юзера).
4. **Живым игрокам уровень задним числом не начисляется.** `last_rewarded_level`
   стартует с 0; сейчас у всех `global_score = 0`, так что вопрос теоретический.
5. **Плашка слома стрика гаснет по текущей механике restore** — то есть после
   восстановления (RPC чистит `lost_streak_len/at`) или по истечении 72-часового окна.
   Начало нового стрика её НЕ гасит: код так работал и до S67, а постановка велела
   механику restore не менять.
6. **Числа админки — семь, а не шесть.** В постановке перечислено шесть, но написано
   «7 чисел»: седьмая настройка — карта наград `level_freeze_rewards`. Иначе выдача
   заморозок оказалась бы хардкодом, что запрещено рамкой постановки.
7. **Расхождение внутри постановки решено в пользу Куска 3.** Смоук-чеклист требовал
   строку «без оценки и наград» внутри свободной сессии, а Кусок 3 прямо запрещает
   новые строки и плашки (решение юзера 02.09 + урок №21). Строки нет; в чек-листе
   ниже этот пункт переписан.
8. **`_resolve_player` теперь возвращает всю строку users.** `finish_session` читал
   users дважды; каждый поход Railway→Supabase ≈ 0.5 с (замер S66). Поведение то же,
   на один запрос меньше.
9. **Коммиты сгруппированы «бэкенд / фронт свободного дня / фронт экранов»,** а не
   строго по кускам постановки: серверная часть кусков 1–3 живёт в одной функции
   `finish_session`, разрезать её по коммитам было бы искусственно.
