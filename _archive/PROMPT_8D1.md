### 1. Разнесение по кубам режима R (П.1a) — отменяет находку №9
Текущая `MentorPlayerPage.tsx` (полуэкранная шторка «всё в одном») разносится на ДВЕ полноэкранные страницы:

**Action (R) = наблюдение и взаимодействие.** Тап по строке игрока → страница НАБЛЮДЕНИЯ:
- досье (см. §2), дарение (капли / заморозка), внизу — строка-дверь «🎁 Полка X/N →» (П.1b: счётчик занятых слотов; тап → полка этого игрока в Market). Управления полкой здесь НЕТ.
- Бейдж «⏳ N» из строк списка Action убрать (его дом теперь Market, см. допущение Д1).

**Market (R) = магазин наставника.** Пул 💧 + «Пополнить» + список игроков; тап по игроку → СРАЗУ его полноэкранная ПОЛКА:
- шапка (П.1c, минимум): маленькое фото + имя + счётчик слотов «X/N» + строка «👤 К профилю →» (тап → страница наблюдения этого игрока). Живых цифр наблюдения (стрик/XP) в шапке НЕТ.
- под шапкой — репутация: «Исполнено обещаний: N» (Д3);
- секция «⏳ Ждут исполнения» (купленные обещания до галочки игрока) — переезжает сюда (Д1); бейдж «⏳ N» — в строку списка игроков Market R;
- лоты (превью, смена цены, перевыставление ↻, убрать), кнопки «➕ Обещание» (рекордер живёт здесь) и «⭐ Предмет».

**Bond** — без изменений (карточка игрока там не нужна).

**Дарение (Action):** в окне дарения показывать остаток пула «Доступно: N💧» + кнопка «Пополнить», открывающая существующий `DropPackModal` поверх (Д2 — шорткат, чтобы пустой пул не был тупиком; сам пул и пополнение канонически живут в Market).

**Навигация:** пара «профиль ⇄ полка» — один тап в обе стороны, работает кросс-куб; «← Назад» возвращает туда, откуда пришёл (оба пути входа на полку: из списка Market и из строки-двери Action). Реализация роутинга — на твоё усмотрение.

**Бэкенд:** `GET /shelf/players/{id}/page` можно оставить одним эндпоинтом или разнести под две страницы — реши сам; инвариант §8.7 сохранить: баланс капель игрока наставнику НЕ отдаётся.

### 2. Полноэкранность (П.2) и досье (П.3)
- Обе страницы — полноэкранные с «← Назад»; полуэкранная шторка в этих местах упраздняется (№17).
- Досье на странице наблюдения: фото квадратом слева (~⅓ ширины), справа имя + чипы-атрибуты СТОЛБИКОМ (пол / цель / подготовка). Ниже ряд из трёх плиток: XP · стрик · рекорд — в каждой цифра крупно → термин → мелкая расшифровка: «XP — очки опыта», «стрик — дней подряд», «рекорд — лучший стрик» (П.3b). Ниже дарение, затем строка «🎁 Полка X/N →».
- XP-прогресс-бар (шкала «до кратного 1000», допущение S56) — удалить (Д4).

### 3. Встроенный плеер видео (П.6a) + тексты кнопок (П.6b)
- Один компонент «плеер-модалка»: `<video>` в окне поверх текущего экрана (затемнение, крестик), src — подписанная ссылка (грузится лениво по тапу). Используется во всех трёх местах: полка наставника (обещание/отчёт), «Мои покупки» игрока, просмотр отчёта наставником.
- `tg.openLink` для ПРОСМОТРА видео выпилить полностью.
- Кнопки на каждой видео-карточке: «▶ Смотреть» (плеер-модалка) + «⬇ Скачать». Слово «галерея» в кнопках не использовать. Скачивание реализуй доступным в webview способом (SDK downloadFile / подписанная ссылка) — запрет внешней вкладки касается только просмотра (Д5).
- Тест на iOS-webview обязателен (капризы видео уже ловили на смоуке) — см. смоук.

### 4. Пустая полка наставника у игрока (П.7)
- Секция «🎁 Полка наставника» на витрине игрока видна ВСЕГДА при активном партнёрстве; пустые слоты — пунктирные ячейки-заглушки, количество = слотам тарифа наставника (сейчас 2/4/6).
- Черновой текст пустой ячейки: «Здесь появятся подарки наставника» (финальный текст будет заменён после эконом-сессии — сделай его легко правимой константой).
- Наставника нет → секции нет (как сейчас).

### 5. «Мои покупки» игрока (П.8b, П.8c)
- **Статусы star_item (№26):** freeze → «✅ +1 заморозка в запасе», photo_reroll → «✅ +1 попытка смены фото», для будущих типов дефолт «✅ Получено». «Выполнено» — только у обещаний.
- **Иерархия кнопок обещания (№19):** всегда ОДНА крупная главная кнопка текущего шага (во всю ширину), вторичные — мелкие в ряд:
  - ждёт исполнения → главная «✓ Отметить выполненным» + мелкая «▶ Смотреть»;
  - галочка есть, отчёта нет → главная «🎥 Приложить отчёт»;
  - закрыто (отчёт есть) → карточка спокойная, только мелкий ряд «▶ Обещание · ▶ Мой отчёт · ⬇ Скачать».
- **Достройка бэка (следствие П.8c, Д6):** сейчас видеоотчёт принимается только вместе с галочкой (`/fulfill`). Нужна возможность приложить отчёт ПОСЛЕ: эндпоинт (или расширение существующего) с гейтами «владелец пары + item fulfilled + отчёта ещё нет». Репутация начисляется на fulfill ОДИН раз — прикладывание отчёта её повторно не растит.

### 8. AI-стилизация: два режима в одной генерации (П.10)
- `photo_styler.py`: ДВА отдельных промпта — «слабая обработка» (максимум портретного сходства, минимум стилизации) и «глубокая обработка» (сильная стилизация). Одна попытка = по-прежнему 2 генерации (COGS не растёт), но теперь это weak+deep, а не 2 случайных.
- В `card_photo_candidates` пометить, какой вариант каким режимом сделан — фронту нужны подписи.
- Экран выбора: ОРИГИНАЛ (селфи) рядом с двумя вариантами, у вариантов подписи режимов (формулировки «слабая/лёгкая/глубокая» — на твой вкус, но понятные не-геймеру). Опция «оставить как есть» (raw): проверь, что она доступна с экрана выбора; если в текущем флоу её там нет — добавь (Д7).
- Реролл — без изменений (существующая прогрессия цен; лимиты обработок — НЕ в этом патче).
- **Таймбокс-тюнинг промптов:** 5–10 живых генераций на фикс-наборе тестовых селфи, лучшие формулировки — в патч. ⚠️ Перед прогоном ОСТАНОВИСЬ и спроси юзера: нужны GEMINI-ключ в локальном env и тестовые селфи (`samples_8d1/`, в `.gitignore`); это платные вызовы API.

### 9. Пресет записи «C» (S57) — оба рекордера (обещание наставника И видеоотчёт игрока)
| параметр | значение |
|---|---|
