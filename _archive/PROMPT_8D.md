### Ф2. Бэкенд — полка, обещания, дарение (новый роутер `shelf.py` или расширение partnerships — реши по структуре)
R (гейт: активная подписка + партнёрство active):
- `GET .../players/{id}/page` — страница игрока: `card_photo_url` (мультяшка-дефолт как в 8c), имя, строка «пол · цель · подготовка» (данные 7.5.1), XP, стрик; полка (лоты + слоты занято/всего по тиру), pending-обещания, репутация «исполнено обещаний на N 💧» (агрегат по fulfilled shelf_items, НЕ денормализовать). Баланс капель игрока R НЕ отдавать (§8.7).
- `POST .../shelf/promise` — создать обещание: видео ≤30 сек (лимит размера как у тренировочных клипов), title, price_drops в админ-лимитах; гейт свободного слота. Видео → бакет promises.
- `PATCH/DELETE .../shelf/{item}` — цена / убрать (active и hidden; purchased не трогать). Hidden star_item можно перевыставить (новая цена/статус active) БЕЗ повторной оплаты Stars.
- `POST .../shelf/star-item` — {catalog_key, price_drops} → Stars-invoice (product_type `shelf_star_item`); fulfill кладёт предмет на полку этого игрока. Инвентаря нет: покупка = сразу выставление.
- `POST .../gift-drops` — {player_id, amount} → RPC + уведомление игроку (бот + notifications, как в 8a). Кап дарения не вводим. «Подарить заморозку» (gift_freeze_balance) остаётся как есть — кнопку перенести на страницу игрока.
- Drop packs: `POST /payments/drop-pack-invoice` {pack_key}; fulfill: `gift_balance += drops`.
- my_players/страница отдают счётчик pending-обещаний для бейджа «⏳ N».

Игрок:
- `GET /players/me/shop` — добавить секции `shelf` (лоты active его пары; превью видео — отдельный эндпоинт подписанной ссылки, грузить лениво по тапу) и `my_purchases` (pending/fulfilled обещания + история трат).
- `POST /players/me/shelf/{item}/buy` — RPC buy_shelf_item; promise → 'purchased' (у R «к исполнению»); нехватка → 400 INSUFFICIENT_DROPS с ценой.
- `POST .../fulfill` — галочка ставится ИГРОКОМ: status='fulfilled' + опциональный видеоотчёт (тот же бакет). Авто-возврата нет, споры — админ вручную (§8.8a п.7).
- `POST .../hide` — «Мне это неинтересно»: status='hidden' + уведомление R.
- «Сохранить в галерею» — эндпоинт подписанной ссылки на скачивание купленного видео/видеоотчёта.
- `begin_card_reroll` (037) доработать: сначала тратить `reroll_credits` (капли не списывать, счётчик прогрессии `card_rerolls` НЕ инкрементить), дальше обычный путь.

Кроны:
- Напоминания R о pending-обещаниях ~раз в 3 дня (last_reminder_at, тихое окно как в 8a).
- Ретеншн §8.8a: fulfilled + 30 дней → удалить видео из Storage, video_path→NULL, строку в 'archived'.

Выпил бустов: activate_boost, ветки оплаты, эндпоинты, фронт-остатки — снести (история payments нетронута).
